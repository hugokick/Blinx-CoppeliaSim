## 3. 总体架构和数据流

### 3.1 主线 V1-07

V1-07 使用一条先规划、后运动的闭环：

```text
独立场景复位
  -> 固定视觉 profile 采集在线相机帧
  -> 主机受控 QR/EAN-13 识别
  -> 像素中心映射到构件世界坐标
  -> payload 经过实验白名单映射到仓位
  -> 全部目标、坐标、置信度和安全参数一次性校验
  -> 学生程序调用现有安全运动/吸盘接口逐件抓取和放置
  -> 场景探针验证仓位占用、吸盘关闭和机器人终态
  -> 保存视觉、路由、命令、事件和终态证据
```

学生程序可以决定已发布目标的处理顺序，但不能提交任意码制、文件路径、ROI、阈值、目标坐标、仓位坐标或命令字符串。视觉命令应保持无参数或仅接受白名单 ID；payload 只作为查表键，绝不能解释为 Python、Lua、shell、CoppeliaSim API 或机器人命令。

### 3.2 并行 D1 纯底座

D1 使用完全独立的内存数据流：

```text
原创合成 BGR 图和 metric depth_m
  -> RGB-D 帧与相机内参校验
  -> 有效深度采样/邻域中值
  -> 针孔模型像素反投影
  -> 可选刚体变换到目标坐标系
  -> JSON 原生的结构化测量结果
```

本轮不读取相机、不连接 CoppeliaSim、不加载外部文件、不启动后台服务，也不把深度结果接入学生 SDK、机器人控制、PyQt、CLI 或正式实验目录。

## 4. 主线开发端：V1-07 正式交付

### 4.1 独立场景

新建独立场景族，建议路径：

```text
simulation/vision_code_routing_lab/
  BL23_vision_code_routing_lab.ttt
  scene_manifest.json
  code_assets_manifest.json
```

场景至少包含：

- BL23/OpenR6 机器人、吸盘、俯视相机和确定性复位脚本；
- 四个可抓取构件，其中同时覆盖 QR 和 EAN-13；
- 至少两个有稳定对象路径和落点锚点的仓位；
- 足够清晰、尺寸固定且来源可证明的原创码面资产；
- 初态、可抓取区域、安全高度、仓位占用和任务终态探针。

不得修改或覆盖现有 `BL23_vision_lab.ttt`、`BL23_vision_quality_lab.ttt`、URDF、STL、机器人网格和现有正式资产。若新场景无法通过真实 CoppeliaSim 在线探针，不得用 mock、回放或静态 fixture 代替在线 PASS。

### 4.2 码制和路由合同

正式课程至少发布一种 QR payload 和一种有效 EAN-13。实验配置维护不可变映射，例如：

```text
payload/code -> part_id -> route_id -> drop_xyz_mm
```

映射中的 code、part、route 和仓位必须全部来自场景清单。出现以下任一情况时，在任何运动前失败关闭：

- 未解码、未知、重复或超出数量上限的代码；
- 同一构件映射到多个仓位，或多个构件占用同一单件仓位；
- 置信度、像素框、世界坐标或安全参数无效；
- 相机、场景版本、profile、机器人或吸盘未就绪；
- 路由计划与场景探针中的对象集合不一致。

完整计划通过校验后才允许运动。运动沿用现有安全世界坐标、速度上限、安全高度、吸盘关闭和回零规则；不得让视觉结果绕过网关直接调用 CoppeliaSim。

### 4.3 学生接口和课程材料

按现有 V1-06 和 R1 闭环模板组合现有模式：

- 主机控制的代码识别接口返回不可变结果、证据引用和经校准的世界坐标；
- `ctx.experiment.info()` 只公开教学所需的码制、路由 ID、安全参数和白名单映射；
- 学生模板先验证全部识别和路由结果，再调用现有 `ctx.robot`、`ctx.tool` 及安全辅助函数；
- PyQt、CLI、PowerShell、正式目录和指导书均提供 V1-07 入口；
- 结果面板展示 raw、annotated、decoded routes、motion events 和 final occupancy，不允许编辑或执行结果字段。

课程成功条件是全部构件进入对应虚拟仓位、机器人回到规定终态、吸盘关闭、无学生子进程残留，并且视觉结果、路由计划和场景终态属于同一次运行。

### 4.4 失败恢复和验收

任何计划阶段失败都不得开始运动。运动阶段失败必须尽力关闭吸盘、停止后续命令并保存失败证据；只有在安全且协议允许时才执行回零，不能用回零异常覆盖主错误。

V1-07 至少包含：

- 码制、payload 白名单、路由计划和坐标合同单元测试；
- 学生协议、SDK、网关、暂停/停止/复位和错误优先级测试；
- 场景对象路径、码面资产、仓位和受保护资产静态测试；
- 使用专用端口和精确进程归属清理的真实 CoppeliaSim 在线验收；
- PyQt 离屏测试及 100%/125% 人工截图检查；
- 全仓静态回归、交付合同和发布清单检查。

仿真通过只证明虚拟闭环。教学效果保留 `PENDING_HUMAN_ACCEPTANCE`；真实海康相机、机械臂、急停、气路和物理抓取保留 `PENDING_HARDWARE`。

## 5. 并行开发端：D1 RGB-D 纯底座

### 5.1 模块边界

建议新增且只在独立路径工作：

```text
vision_platform/rgbd/
tests/test_rgbd/
docs/superpowers/specs/2026-08-02-d1-rgbd-kernel-design.md
docs/superpowers/plans/2026-08-02-d1-rgbd-kernel-plan.md
```

最小能力包括：

- `CameraIntrinsics`：`fx`、`fy` 为正有限值，`cx`、`cy` 有限，图像尺寸为正整数；
- `RgbdFrame`：BGR `uint8 HxWx3` 与 `float32 HxW depth_m` 同尺寸；
- 深度值以米为单位，有限正值有效，`0` 表示无效，不允许 NaN/Inf 进入正式结果；
- 固定边界的单像素/奇数邻域深度采样，返回中值、有效像素数和失败码；
- 针孔模型反投影 `(u, v, z) -> (x, y, z)`，坐标约定和像素中心规则明确；
- 只接受显式 4x4 有限刚体变换的点坐标变换；
- 结果可转为 JSON 原生标量/列表，不包含 NumPy 标量、路径或不可序列化对象。

不引入 Open3D、ROS、深度相机 SDK、网络模型或新大型依赖。暂不实现稠密点云、配准、SLAM、抓取规划和真实传感器噪声模型。

### 5.2 原创测试数据和失败合同

测试数据由代码生成平面、台阶、方块高度、倾斜面、空洞和边界像素，使用固定随机种子且不写图片文件。至少验证：

- 中心点和图像边界反投影；
- 已知平面/方块深度与三维坐标误差预算；
- 零深度、邻域全无效、尺寸不匹配、非法 dtype、非法内参和非法变换；
- 输入数组不被修改、重复运行结果相同、512x512 CPU 处理有明确上限；
- 序列化结果全部为有限 JSON 原生值。

该分支只能声称“D1 RGB-D 纯数据与算法底座通过”。CoppeliaSim RGB-D、D1-01～D1-03 正式课程、学生 SDK、PyQt、机器人闭环、Orbbec/奥比中光和其他硬件均保持未验收。
