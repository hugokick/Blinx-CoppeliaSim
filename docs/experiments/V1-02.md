# V1-02 像素尺寸与构件尺寸测量

## 实验目标

在 CoppeliaSim 视觉质检场景中，对三个彩色标准构件执行一次受控二维分析，
读取中心、长边、短边和面积，理解像素尺寸如何在显式仿真比例尺下换算为毫米
尺寸。学生需要说明比例尺、测量平面、轮廓离散和成像误差之间的关系。

## 安全边界

学生程序只调用公开 SDK。`ctx.vision2d.analyze()` 不接受 ROI、阈值、比例尺、
文件路径、对象路径或 Remote API 参数；这些值来自经过发布的实验定义。程序
不下发机械臂运动、吸盘或抓取命令，也不直接导入 OpenCV 或平台算法模块。

本实验不连接海康相机，不驱动真实机械臂，不验证急停、气路或物理抓取。
仿真比例尺只适用于 `standard` 配置和当前虚拟测量平面，不能写成真实测量精度
或真实相机标定结论。

## 发布配置

| 项目 | 发布值 | 说明 |
| --- | --- | --- |
| 相机配置 | `standard` / 512 × 512 | 固定基线配置 |
| 分析区域 | `[180, 180, 335, 340]` | 原图坐标，右边界和下边界不包含 |
| 目标数量 | 3 | 圆、矩形、三角形彩色标准件 |
| X/Y 比例尺 | 1.4433756729740643 mm/px | 当前虚拟测量平面 |
| 分割方式 | HSV 饱和度和亮度下限 | 宿主端固定参数 |

ROI 之外的像素在同尺寸副本中置零，检测坐标仍使用 512 × 512 原图坐标，不因
裁剪发生平移。

## 学生步骤

1. 读取 `ctx.experiment.info()`，确认 `analysis_focus` 为 `size`；
2. 检查发布的分析配置档在 `allowed_profile_ids` 中；
3. 应用 `standard` 配置档；
4. 调用一次 `ctx.vision2d.analyze()`；
5. 确认状态为 `PASS` 或 `PARTIAL`，并得到三个标准件；
6. 对每个目标读取 `long_side_px`、`short_side_px`、`area_px2`、
   `size_mm` 和 `area_mm2`；
7. 记录像素与毫米尺寸并留下 checkpoint；
8. 无论成功或失败，都在 `finally` 中恢复基线配置，同时保留原始异常。

## 五层运行证据

每次正式分析产生同一个结果包，包含五层图像：

1. `raw`：CoppeliaSim 原图；
2. `roi-input`：ROI 外置零的算法输入；
3. `foreground-mask`：初始前景掩膜；
4. `cleaned-mask`：形态学清理后的掩膜；
5. `annotated`：轮廓、中心、检测 ID、颜色和形状标注图。

结果 JSON 同时保存像素和仿真毫米字段。每个图层都记录路径、尺寸和 SHA-256，
用于复核本次运行，而不是作为课程成绩。

## 结果复核与思考

1. 比较三个构件的长边、短边和面积，确认数值均为有限正数；
2. 说明为什么像素尺寸必须结合测量平面上的比例尺才能换算毫米；
3. 说明轮廓近似、像素化、边缘位置和形态学操作如何影响测量；
4. 说明仿真针孔模型的比例尺为何不能替代真实相机内参和畸变标定；
5. 比较 `raw`、两层掩膜和 `annotated`，解释每一层的用途。

## automated checks

- `standard_profile`：分析时和最终复位后均为 `standard`；
- `three_targets`：正式场景得到三个发布标准件；
- `size_fields`：像素与仿真毫米尺寸字段完整、有限且为正；
- `five_layer_evidence`：五个固定图层及其哈希可复核。

这些检查只验证软件和仿真证据完整，不是课程成绩，也不证明真实测量精度。

## human checks

- 学生能够解释像素尺寸、比例尺和毫米尺寸的关系；
- 学生能够指出测量平面、轮廓离散、相机模型和真实标定的误差来源。

上述教学判断必须由教师或验收人员完成，当前为
