# V1-07 二维码与条形码识别及仓位路由

## 实验目标

在独立的 CoppeliaSim 场景中，学生通过公开 SDK 识别两个 QR 和两个 EAN-13，理解码制、载荷白名单、路线计划与机器人动作之间的边界。路线由主机根据固定发布清单生成；学生可以选择执行顺序，但必须在任何移动前完成完整计划校验。

四个固定绑定为：`V1-07-A` → `part_a` → `route_red/red_1`，`V1-07-B` → `part_b` → `route_blue/blue_1`，`6901234567892` → `part_c` → `route_red/red_2`，`6901234567809` → `part_d` → `route_blue/blue_2`。

## 安全边界

学生模板只能使用公开的 `ctx.experiment`、`ctx.camera`、`ctx.vision2d`、`ctx.robot`、`ctx.tool`、`ctx.log` 和 `ctx.checkpoint`。不得导入 OpenCV、NumPy、CoppeliaSim Remote API、文件系统或进程 API，也不得把识别载荷当作代码、命令或路径执行。主机在配置、场景、资产、路线、运动高度和工具状态上拥有最终控制权。

仿真动作使用安全高度 110 mm、发布的抓取高度 18 mm、速度 15 mm/s 和受控吸盘；路线计划缺失、条目不完整、载荷不匹配、置信度不足或任何顺序错误都必须失败关闭。

## 操作步骤

1. 在“实验目录”选择 `V1-07`，检查实验信息中的 `standard` 配置档、四条路线和 `PENDING_HARDWARE` 状态。
2. 调用 `ctx.camera.apply_profile("standard")`，再调用 `ctx.vision2d.code_routes()` 获取同次运行的原始、标注和路线证据。
3. 在动作前验证状态为 `PASS`、条目数为四、四个 `entry_id`、part、码制、载荷、路线和 drop 坐标均与白名单一致，并确认安全高度与速度未被改变。
4. 学生可按 `entry_id` 或自己解释的顺序执行四次受控取放；每次都必须经过悬停、取件、吸取、抬升、放置和释放的主机守卫。
5. 调用 `ctx.robot.home()`，保存 checkpoint；无论成功或失败，都在 `finally` 中关闭工具并恢复视觉配置档。

## 证据说明

同次运行证据包包括 `raw` 相机帧、`annotated` 标注帧、`routes` 路线计划、每次运动和工具事件、初态/末态探针、最终红蓝仓位占用和 `summary.json`。证据只用于复核识别、计划先行、受控动作和状态收尾，不是成绩或自动评分。`plan_id`、资产清单哈希、场景清单哈希和配置档哈希用于确认绑定关系。

## 错误解释

- `CODE_ROUTE_PLAN_INCOMPLETE`：未得到四条完整路线，禁止任何移动；
- `CODE_ROUTE_WHITELIST_MISMATCH`：part、码制、载荷、路线或坐标不在发布白名单；
- `CODE_ROUTE_SEQUENCE_INVALID`：未按主机守卫顺序执行，系统进入失败关闭；
- `VISION_PROFILE_BACKEND_UNAVAILABLE`：相机、配置档或场景路径不匹配；
- `ROBOT_SAFETY_VIOLATION`：高度、工作空间或运动反馈越界；
- `TOOL_SAFETY_VIOLATION`：吸盘状态与动作阶段不一致。

出现错误时，先查看错误码和同次运行证据，再恢复 profile、关闭工具并重新加载场景；不要通过放宽阈值、修改路径或绕过网关来“修复”。

## 自动检查

自动检查覆盖标准配置档、四个代码、完整路线计划、计划先行、四次守卫取放、最终仓位占用、回零、工具关闭和同次运行证据。静态测试中的 CoppeliaSim skip 不能写成在线 PASS；只有显式启用并保存真实输出的在线验收才可记录虚拟闭环通过。

## 人工验收

教学效果保持 `PENDING_HUMAN_ACCEPTANCE`。学生需要口头说明 QR 与 EAN-13 的编码/校验差异、白名单路由、计划先行和失败关闭，并解释为什么同一个 `plan_id` 关联了图像、路线和动作证据。教师还应观察学生是否能在不改动主机配置的情况下选择执行顺序并定位一个故障。

## 真机迁移边界

仿真通过不代表教学效果、海康相机、真实机械臂、急停、气路或物理抓取验收通过；前者保持 PENDING_HUMAN_ACCEPTANCE，后者保持 PENDING_HARDWARE。

迁移到实验室时，只能把学生模板中的公开 SDK 调用映射到经过审核的真实相机、机器人和吸盘适配器；需要重新进行视觉精度、可达性、速度、急停、气路、物理抓取和人工验收，不能直接把仿真 PASS 当成硬件结论。
